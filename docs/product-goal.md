# Litra — 产品目标与验收（v0.1）

> 本文是交给 GPT 的开发目标。UI 以根目录的 `mockup.html` 为参考；`docs/apple-books-ui-spec.md` 是历史稿，和本文冲突时以本文 + `mockup.html` 为准。
>
> 原型只是参考，允许用更现代的 Material 3 排版重构，不要做像素级克隆。

---

## 0. 一句话目标

做一个原生 Android 本地 EPUB 阅读器：**主页 / 书库 / 搜索** 三个 Tab，Material 3，Kotlin + Compose，Readium 解析 EPUB，具备书库管理、阅读器、阅读目标、书籍详情和设置。

---

## 1. 范围

### V1 必须做

- 本地导入 EPUB 2/3；
- 主页、书库、搜索；
- 书库双列封面视图 + 列表视图；
- 藏书选项、已读完时间线；
- 书籍详情页；
- 阅读器（目录、书内搜索、进度、书签、排版设置）；
- 阅读目标与周期打卡；
- 设置页；
- 本地持久化，无网络依赖。

### V1 不做

- 书店、购买、账号、云同步；
- 社交、书评、关注；
- DRM / LCP；
- 有声书播放；
- 全库正文索引；
- iOS 像素级复刻；
- Apple 字体、SF Symbols、Apple 图标或截图。

> PDF / 有声书入口可以在 UI 中保留为占位，但 **V1 首发只承诺 EPUB**。不要为了占位入口阻塞 EPUB 闭环。

---

## 2. 体验原则

1. **Material 3 原生**：NavigationBar、TopAppBar、FAB、ModalBottomSheet、ListItem、SearchBar、Switch、Slider 等优先用 M3 组件。
2. **现代排版**：留白、层级、卡片节奏可以比原型更现代；不要堆阴影和渐变。
3. **内容优先**：封面、书名、阅读进度是主角；控件退后。
4. **底部三 Tab 固定**：主页、书库、搜索。其余页面都是二级页面。
5. **Android 原生交互**：系统返回、预测性返回、SAF 文件选择器、分享、触觉反馈。
6. **无 Apple 资产**：不要打包 SF Pro、SF Symbols、Apple 插画或图标。

## 4. 关键行为（必须严格实现）

### 4.1 阅读进度与已读完

这是 V1 最容易做错的地方：

- 读到书末时，进度**最高记为 99%**，不要自动变成 100%。
- 99% 状态不显示对号、不加“已读完”徽章。
- 主页横向卡片到达 99% 后：
  - 不再显示进度百分比；
  - 不再显示书籍类型标签；
  - 只显示一个 **“点击标记读完”** 按钮。
- 用户点击“点击标记读完”后：
  - `status = FINISHED`；
  - 书库封面外显示 **“已读完”** 文字，不显示 100%，不加对号；
  - 即使重新打开并翻到中间，状态仍然是“已读完”，不能自动退回 `READING`。
- “已读完”是一个持久状态，不是由进度百分比反推的。
- 书库列表和主页“今年读过”不再用封面角标对号表示完成。

### 4.2 书籍类型

- 横向卡片上的类型小标签只有两种：**图书 / 漫画**。
- 99% 的卡片不显示类型标签。
- 类型标签可以出现在进度条左侧，但不要扩展到“文学 / 科技 / 科幻”等自定义分类；那些属于藏书分类，不是书籍类型。

### 4.3 主页

- 五个区块，之间有横向分隔线：
  1. 继续阅读（横向滚动卡片）
  2. 欲读清单（大封面，横向；封面外左下角显示百分比，无背景）
  3. 之前读过（横向卡片；99% 时只显示标记按钮）
  4. 阅读目标（自定义周期/时长，打卡记录）
  5. 今年读过（封面，无对号）
- 横向卡片：
  - 左封面；
  - 右侧上方大字号书名，下面作者；
  - 底部左侧类型标签 + 进度；99% 时只留按钮。
- 点击封面 → 书籍详情；点击非封面信息区 → 直接阅读。
- 长按卡片 → 操作菜单：阅读、加入欲读清单、标记已读完、加入分类、图书信息、移除。

### 4.4 书库

- 默认双列封面：一行两个；不显示书名、作者。
- 进度显示在**封面外左下角**，纯文字，无背景；
- 已标记完成的显示“已读完”，不是 100%，不加对号；
- 右下角悬浮按钮：
  1. 导入；
  2. 筛选 / 排序 / 视图（含切换到列表）；
  3. 藏书选项；
- 列表视图：左封面、右书名；
- “图书”分类 = 所有导入内容，不是只筛 EPUB；
- 保留 PDF / 有声书入口时，要有空状态和明确的“暂不支持”。

### 4.5 藏书选项

- 全屏页面，覆盖底栏；左上只保留返回箭头，不显示“书库”文字。
- 不显示“系统分类 / 我的分类”标题。
- 选中的分类用**加深背景**表示，不要用对号，也不要用阴影作为唯一选中标识。
- 自定义分类行前有复选框；
- 右下角只有一个悬浮按钮：
  - 初始为“标记”，点击进入选择；
  - 选中自定义分类后，同一个按钮自动变为“删除分类”；
  - 未选中时不可删除；系统分类不可删除。
- 选择普通分类后返回上一个页面并应用；选择“已读完”进入独立时间线页。

### 4.6 已读完

- 独立页面，没有底部栏，没有“书库”标题；
- 顶部只有返回和“已读完”；
- 内容为按完成时间组织的时间线；
- 从藏书选项的“已读完”进入。

### 4.7 搜索

- 搜索框 + 搜索记录；没有记录时整块不显示；
- 输入后显示结果；
- 右下角悬浮“设置”按钮，进入设置页；
- 不做搜索建议、热门搜索、书店搜索。

### 4.8 书籍详情

- 海报从屏幕顶端延伸到状态栏下面，再渐入下半部分；
- 下半部分内容居中；
- 用矩形卡片分隔内容（例如“内容简介”“出版信息”）；
- 标签来自真实分类和元数据，不要随便编：
  - 分类：图书 / 漫画 / 自定义分类；
  - 元数据：语言、格式、文件大小等。
- 右下角悬浮“阅读”按钮。

### 4.9 阅读器

- 背景独立于 App 深色模式；
- 顶部：返回、书名、书签、更多；
- 底部：章节/进度、滑杆、目录、搜索、书签、排版；
- 书内搜索使用 Readium SearchService；
- 目录使用 `publication.tableOfContents`；
- 退出保存 Locator；回到阅读器恢复位置；
- 字号、行距、页边距、对齐、滚动/翻页可调。

### 4.10 阅读目标

- 周期：每天 / 每周 / 每月；
- 自定义目标分钟数；
- 阅读时长自动累计；
- 达到目标后写入周期打卡记录；
- 记录包括周期、分钟数、是否达标；
- 修改目标只影响后续周期，不重算历史。

## 5. 技术目标

### 5.1 技术栈

- Kotlin 2.4.x；
- Jetpack Compose + Material 3；
- Navigation Compose；
- Room + KSP；
- Hilt；
- Coil；
- DataStore；
- Readium Kotlin Toolkit 3.4.0（EPUB）；
- minSdk 24，compileSdk 37；
- 单 Activity，MVVM + Repository，单向数据流。

> 版本以实际可编译为准；如果 SDK 37 不可用，可以降到 Readium 可用的最低 compileSdk，但要在 README 说明。

### 5.2 Readium

- 导入时用 `AssetRetriever` + `PublicationOpener` 解析 EPUB；
- 封面用 `publication.coverFitting(...)`，缩放到合理尺寸；
- 阅读器优先用 Readium 3.4.0 的 Compose Web Navigator（`ReflowableWebRendition`）；
- 如果该实验 API 在实际工程中不稳定，可以退回 `EpubNavigatorFragment` 并用 `AndroidView` 承载，但 UI 外壳保持 Compose；
- 进度保存完整的 `Locator`；
- 书内搜索使用 Readium `SearchService`；
- `Publication` 在退出阅读器后关闭。

### 5.3 数据规则

- `books.status`: `UNREAD / WANT_TO_READ / READING / FINISHED`；
- `books.format`: `EPUB / PDF / AUDIOBOOK`（V1 实际只导入 EPUB）；
- `current_locator_json` 保存完整 Locator；
- 已读完状态不要因为进度变化自动回退；
- 阅读会话 `reading_sessions` + `goal_check_ins` 用于目标和打卡；
- 搜索记录最多 10 条，无记录不显示。

### 5.4 质量

- 单元测试覆盖：进度 99% 规则、标记完成、完成状态持久化、目标周期计算；
- Compose UI 测试覆盖：三个 Tab、书库切换视图、书库到列表、搜索记录隐藏/显示、标记读完按钮；
- Release 构建能通过 R8；
- 深色模式、字体缩放 2.0、TalkBack 基本可用。

## 6. 里程碑

### M0 — 仓库与骨架

- 创建 GitHub 仓库、初始化 Android 工程；
- Compose + M3 主题、三 Tab 导航；
- 10 个页面路由占位；
- CI：`assembleDebug` + 单元测试 + lint；
- README、分支策略、首条提交。

验收：GitHub 上有仓库；main 能构建；CI 绿。

### M1 — 书库与导入

- Room 数据层；
- EPUB 导入（SAF）、元数据/封面提取；
- 双列书库、列表视图、进度文字；
- 藏书选项页（全屏、加深选中、复选框、标记→删除单按钮）；
- 已读完独立时间线；
- 右下角 FAB。

验收：导入 10 本 EPUB；切换分类；切换列表；删除自定义分类；重启数据仍在。

### M2 — 阅读器与进度

- Readium 打开 EPUB；
- 阅读器 UI；
- 目录、书内搜索、书签、排版设置；
- 99% 规则、手动标记读完、完成状态持久化。

验收：读到末尾是 99%；主页可标记；标记后重读中间仍显示已读完；退出重进恢复位置。

### M3 — 主页、目标、搜索

- 五个主页区块；
- 横向卡片、欲读大封面、完成按钮、类型标签；
- 阅读目标页、周期打卡；
- 搜索页、记录、结果、设置 FAB。

验收：所有交互闭环；99% 卡片只显示按钮；没有搜索记录时区块不渲染。

### M4 — 详情、设置、打磨

- 书籍详情页（全出血海报、居中卡片、真实标签）；
- 设置页；
- 长按卡片菜单；
- 深色模式、无障碍、空状态、错误状态；
- 性能与内存检查。

### M5 — 发版

- 修 P0/P1；
- 版本号 `v0.1.0`；
- 构建 release APK；
- GitHub Release 附 APK + release notes；
- 更新 README / CHANGELOG。

## 7. Git / GitHub / 发版（由 GPT 执行）

- 仓库名：`litra-readium`；默认分支 `main`；公开仓库；如已存在则复用。
- 提交规范：Conventional Commits，例如 `feat: ...`、`fix: ...`、`chore: ...`。
- 分支：`feat/...`、`fix/...`；每个里程碑至少一个 PR（可自我合并），保留记录。
- 不提交 keystore、token、本机路径、`.DS_Store`。
- CI：GitHub Actions；
  - push/PR：assembleDebug、unit test、lint；
  - tag `v*`：构建 APK 并创建 GitHub Release。
- 首发版本：`v0.1.0`（preview）。没有正式签名时，Release 使用 debug APK，并在 notes 里明确“preview / debug signed”。
- **只发一个版本**：不要按里程碑/PR 打 tag，不创建 nightly/alpha/beta 等多个 Release；完成全部核心验收后再创建 `v0.1.0`。
- 发布前必须：CI 绿、README 有截图/功能说明、安装包能安装并打开一本 EPUB。

## 8. Definition of Done

- 所有 V1 页面可用，不是空壳；
- 能导入 EPUB、阅读、退出恢复、标记完成；
- 99% / 已读完规则完全符合；
- 书库双列 + 列表、藏书选项、已读完时间线、详情、设置、目标均可用；
- 没有明显崩溃、OOM、数据丢失；
- 测试和 CI 通过；
- GitHub 仓库、README、Release 完成；
- 代码结构清晰，后续可加 PDF / 有声书 / 云同步。
