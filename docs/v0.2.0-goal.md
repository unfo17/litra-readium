# Litra v0.2.0 — UI refresh + missing features

> GPT implementation brief. Current baseline: `v0.1.0` plus the merged post-release hardening on `main` (`f36291e`).
>
> **No tag, no GitHub Release, no version bump in this pass.** Merge to `main` only after full verification. We will decide the release after review.

## 1. Hard constraints

- Keep all existing product rules:
  - reading progress capped at 99%;
  - no checkmark on covers;
  - 99% home cards show only “点击标记读完”, no progress/type;
  - `FINISHED` persists when reopening in the middle;
  - type tags only 图书 / 漫画;
  - library progress text outside the cover, no background;
  - “图书” = all imports.
- Do not use Apple assets.
- Do not add a new release or tag.
- Work on `feat/v0.2.0`; one or more PRs is fine, but no milestone tags.
- Prefer real implementations over placeholder screens.
- Keep the app local-only; no analytics, no network permission unless a feature truly requires it.

## 2. Home: hide empty modules

- Sections that are **hidden completely when empty** (including title, divider and spacing):
  - 继续阅读
  - 欲读清单
  - 之前读过
- Always show:
  - 阅读目标
  - 今年读过 (with a purposeful empty state + count)
- If only goal + year have content, the home screen should still look intentional and balanced, not like a broken empty page.
- Remove orphan dividers; spacing should collapse cleanly.
- Add Compose tests for empty/non-empty combinations.

## 3. Reader: center-tap chrome

- Tapping the center of the reading page toggles:
  - top bar (back, title, bookmark, more);
  - bottom controls (progress, prev/next, TOC, search, bookmarks, typography);
  - system status/navigation bars (immersive).
- Chrome starts visible; hidden state is edge-to-edge and distraction-free.
- Animate show/hide (fade + slide), not a hard jump.
- Preserve text selection, links and normal page gestures as much as technically possible.
- If the Readium WebView cannot forward center taps reliably, use a **center-only transparent tap zone** and document the tradeoff; do not block the whole page.
- Add a subtle scrim/gradient behind visible chrome so text remains readable.
- Optional if clean: left/right edge tap zones for previous/next page; do not break selection/links.
- Add reader brightness control (screen/window brightness, not app theme) in the reader controls/settings if it fits the existing UI.

## 4. UI refresh

Make the app feel like one designed product, not assembled screens:

- Warm Material 3 palette; consistent typography scale, spacing, corner radii and surface tones.
- Edge-to-edge layout; correct status-bar icon contrast in light/dark.
- Home: stronger section hierarchy, cleaner cards, consistent covers/progress.
- Library: balanced 2-column grid, cleaner progress labels, good empty/loading/error states.
- Search: polished search field/history/results; no history block when empty.
- Detail: full-bleed poster, centered metadata chips, clean rectangular cards, good FAB placement.
- Settings/Goals/Collections/Finished: grouped sections, consistent list rows, no duplicated labels.
- Reader: polished chrome, progress bar, sheet for typography/search/TOC/bookmarks.
- Motion: navigation transitions and animated visibility for home sections/reader chrome; avoid gratuitous animation.
- Haptics on meaningful actions (long press, finish, delete) if easy.
- Dark mode and font scale 2.0 must remain usable.
- Update four+ real screenshots in README after the refresh.

## 5. Missing features to add

These are the highest-value gaps; implement end-to-end.

### 5.1 Open EPUB from other apps

- Add `ACTION_VIEW` support for `application/epub+zip` (and `application/octet-stream` only if the URI is actually an EPUB).
- Handle cold start, warm `onNewIntent`, and multiple URIs.
- Copy/import through the existing repository; if the hash already exists, open the existing book instead of duplicating.
- After import, go to detail or reader with a sensible loading/error state.
- Works from a file manager / share sheet without granting broad storage permission.
- Add an instrumentation test for the intent path.

### 5.2 Backup and restore

Add a real local backup/restore, not a fake button:

- Settings → “备份与恢复”.
- Export a `.litrabackup` zip through SAF containing:
  - versioned manifest;
  - books, categories, memberships, bookmarks, reading sessions, goals, check-ins, search history;
  - EPUB files and covers (so restore is actually useful).
- Restore through SAF:
  - validate manifest/version, protect against zip-slip and oversized entries;
  - merge by SHA-256; preserve `FINISHED`, progress, locator, `finishedAt`;
  - handle conflicts deterministically (do not overwrite a newer `lastReadAt`/`finishedAt` with older data);
  - copy files safely; leave no partial rows/files on failure.
- Show progress/success/failure UI; no silent failure.
- Add unit tests for manifest serialization, zip-slip rejection, merge conflict rules, and a device test for export/restore round-trip if practical.

### 5.3 Reader polish

- Add a font-family choice (system serif / sans) if Readium supports it cleanly.
- Keep existing sizes, line height, margins, justification, theme and scroll mode.
- Remember reader settings across books.
- Add a first-open hint for center-tap? Only if subtle and dismissible.
